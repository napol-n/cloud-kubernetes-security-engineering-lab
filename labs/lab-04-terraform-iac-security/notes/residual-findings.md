These findings were reviewed individually rather than automatically remediated solely to obtain a zero-finding scan.

## AWS-0089 — Logging Disabled on Logging Destination Bucket

### Finding

Trivy reports that the dedicated `access_logs` bucket does not itself have S3 server access logging enabled.

### Context

The bucket exists specifically as the destination for server access logs generated by the primary application data bucket.

Enabling server access logging for this bucket would require another logging destination bucket. Applying the same control recursively would create an additional logging tier without providing meaningful security value for the scope of this lab.

### Disposition

**Accepted — Contextual Exception**

The primary application data bucket has server access logging enabled. The dedicated logging destination bucket is intentionally excluded from additional recursive access logging.

## AWS-0132 — Customer-Managed KMS Encryption

### Finding

Trivy reports that the logging destination bucket does not use a customer-managed KMS key.

### Context

The logging destination uses SSE-S3:

```hcl
sse_algorithm = "AES256"

The scanner guidance explicitly notes that SSE-KMS is not supported for S3 server access logging destination buckets and recommends SSE-S3 for this use case.
Disposition
Accepted — Technical Exception
The logging destination intentionally uses SSE-S3 because it is the compatible encryption mechanism for this server access logging scenario.
This exception does not apply to the primary application data bucket, which uses a customer-managed KMS key with key rotation enabled.
Final Assessment
The baseline contained seven detected misconfigurations.
Applicable findings were remediated through:
- S3 public-access blocking
- versioning
- server access logging
- customer-managed KMS encryption for application data
- KMS key rotation
- versioning of the logging destination
- SSE-S3 encryption of the logging destination
The final scan contains two reviewed residual findings, both associated with the dedicated logging destination bucket and both retained with documented justification.
The final security decision is therefore based on contextual risk analysis rather than scanner output alone.
